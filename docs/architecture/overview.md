# Aether Architecture Overview

## 1. Высокоуровневая идея

Aether — это **полиморфное нативное ядро**.

Ядро само по себе не является Linux, Windows или Android.  
Оно предоставляет минимальный набор примитивов:

- Управление физической и виртуальной памятью
- Capability-based контроль доступа
- Планировщик задач (потоков)
- Межпроцессное/межличностное взаимодействие (IPC)
- Загрузку и выгрузку модулей личностей

Поверх этих примитивов динамически загружаются **Личности (Personalities)**.

## 2. Основные сущности

### 2.1 Ядро (Aether Core)
Нейтральное, минимальное, не принадлежит ни одной экосистеме.

### 2.2 Личность (Personality)
Загружаемый модуль, который реализует:
- Формат исполняемых файлов (ELF / PE)
- Таблицу системных вызовов
- Модель процессов и потоков
- Базовые объекты (файлы, сокеты, окна и т.д. — через capability)

Личность может быть полностью выгружена, когда ни один процесс этой личности больше не существует.

### 2.3 Процесс
Всегда принадлежит ровно одной личности.  
Не может сменить личность во время жизни.

### 2.4 Capability
Единица доступа ко всем ресурсам ядра.  
Никаких глобальных прав. Всё только через capabilities.

## 3. Жизненный цикл личности

1. В системе нет ни одной загруженной личности (или есть только минимально необходимые).
2. Пользователь/Domain Manager запускает программу определённой личности.
3. Ядро подгружает модуль личности (если ещё не загружен).
4. Создаётся процесс с этой личностью.
5. Когда последний процесс личности завершается — личность может быть выгружена:
   - Код личности
   - Данные личности
   - Связанные структуры ядра
6. Память возвращается в общий пул.

## 4. Поддерживаемые личности (цель)

| Личность   | Приоритет | Комментарий                                      |
|------------|-----------|--------------------------------------------------|
| Linux      | Высокий   | Базовая и самая важная для первой версии         |
| Android    | Средний   | Строится поверх Linux-механизмов + свой runtime  |
| Windows    | Высокий   | Нативная личность (PE + NT-совместимый слой)     |

macOS сознательно исключён.

## 5. Принципы дизайна

- **Extreme Laziness** — ничего не должно находиться в памяти без необходимости.
- **Zero Legacy Host** — нет «основной» ОС, от которой всё зависит.
- **Native First** — личности исполняют бинарники нативно, без трансляции инструкций процессора.
- **Capability Security** — вся безопасность строится на capabilities.
- **Hot-pluggable Personalities** — личности можно добавлять и убирать без перезагрузки ядра.

## 6. Что НЕ является целью

- Полная 100% совместимость с Windows 11 в первой версии
- Поддержка macOS
- Классическая виртуализация как основной механизм
- Эмуляция процессора (QEMU-style)
