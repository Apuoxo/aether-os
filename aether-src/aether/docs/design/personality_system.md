# Система личностей (Personality System)

## Назначение

Личность — это загружаемый модуль, который даёт ядру возможность исполнять программы определённой экосистемы нативно.

## Жёсткие требования

1. Личность должна иметь возможность быть **полностью выгруженной** из памяти.
2. Пока личность выгружена — в памяти не должно оставаться её кода и данных.
3. Загрузка личности происходит лениво (только при первом реальном использовании).
4. Процесс навсегда привязан к одной личности.

## Структура модуля личности (черновик)

```text
Personality Module
├── Header
│   ├── Magic
│   ├── Version
│   ├── Personality ID (Linux / Android / Windows)
│   └── Entry points
├── Code section          (выгружаемая)
├── Read-only data
├── Syscall table
├── Binary format handler (ELF / PE loader)
└── Private data (если нужно)
```

## Основные операции ядра над личностями

- `personality_load(id)` — загрузить модуль в память и зарегистрировать
- `personality_unload(id)` — полностью выгрузить (только если нет живых процессов)
- `personality_get(id)` — получить capability на личность
- `process_create(personality_cap, image)` — создать процесс указанной личности

## Выгрузка

Когда счётчик процессов личности достигает нуля, Personality Manager может:

1. Заморозить все связанные структуры
2. Освободить все страницы кода и данных личности
3. Удалить регистрацию syscall-таблицы
4. Вернуть память в общий аллокатор

Это одно из самых важных свойств Aether.

## Linux Personality

- Нативный ELF-загрузчик
- Таблица Linux syscalls
- Минимальный POSIX-совместимый слой

## Android Personality

- В значительной степени использует механизмы Linux Personality
- Добавляет: Binder, ART-runtime интеграцию, Android-specific init и permissions

## Windows Personality

- PE-загрузчик
- Минимальный NT syscall слой
- Постепенное наращивание Win32-совместимости
- Цель — нативное исполнение, а не эмуляция
